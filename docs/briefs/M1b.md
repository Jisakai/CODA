## Required behavior
- 4/4, eight quantized eighth-note slots per bar. Pattern overlay only while tweaking, over the BIG chord roll, never a permanent lane or squeeze into the short chord strip.
- Pencil top-half touchdown starts downward low-to-high stroke; bottom-half touchdown starts upward high-to-low stroke. Latest explicit owner requirement: arrow lengths snap to TEN discrete increments of the pattern editing area height. Levels 1...10 map to 10%...100% velocity, with full-height length = 100% and one tenth = 10%. Use the SAME quantized value for rendered arrow, live readout and stored/base playback velocity; no continuous length-to-velocity mapping. Zero means no stroke, not an eleventh audible level. Existing stroke drag edits; Pencil tap existing stroke removes. Finger never edits/auditions music; no pressure/tilt/barrel double-tap fallback. This quantization does NOT apply to chuck-circle size without further owner instruction.
- A roughly closed circular gesture creates chuck (X); circle size controls velocity. Explicit closure/minimum size/path-length criteria prevent taps and short drags becoming chuck. Centralize tunables and cover false positives/cancellation.
- Empty slot triggers NO new stroke and does NOT prematurely stop a preceding sound. Actual chord end/rest/loop boundaries remain respected. No pattern means exact existing block-chord behavior.
- Down/up use sorted pitches, opposite onset order, same existing synth and sample-accurate transport. Chuck is a short percussive dead-string rake on ANY of the three presets, with short envelope/filter snap/noise burst; never a second audio engine or guitar sample.
- Swing delays off-beat eighths deterministically; humanize is a separate Tight/Loose switch with small random timing/velocity plus subtle per-note detune/filter. Spread spans approximately 0–60 ms; humanize timing approximately ±3 ms, velocity ±6. Named tunable defaults/ranges; do not claim exact values where spec gives approximation.
- Apply patterns to bar ranges. Adopt OPEN stated default whole loop behind ONE named scope default; retain range model rather than per-chord performance mode. Pattern changes must be undoable transactions with no preview history pollution. No persistence/export needed.
- Include data-driven preset pattern, e.g. SPEC's eight-slot Pop Rock pattern D · D U · U D U. Arpeggio behavior has NO complete default and is outside M1b: no invented arp UI or implementation.

## Architecture and current interfaces to inspect
- CodaMusic/NoteEventCompiler.swift is currently Foundation-only block compiler. NoteEvent carries integer stepOffset and sampleOffset, NOT velocity or fractional onset. CompiledLoop preserves cycle-indexed rounding. Do not pretend existing grid format can express microtiming.
- CodaSession/MusicSession.swift currently converts NoteEvent.stepOffset to native CodaGridEvent and would discard extra timing unless deliberately adapted.
- Sources/CodaTransport/include/coda_transport.h currently has fixed POD CodaGridEvent(step,region,kind,pitch,rank,reserved), 3072 events, four plan slots; render recomputes timing from samples_per_step. Inspect all admission, seek/restore/audition, region identity, event-order and ownership code before extending.
- CodaDSP/include/coda_dsp.h currently has only ON/OFF and no velocity/humanize/chuck payload. Inspect DSP same-region/voice-rank assumptions: staggered strokes/repeated notes MUST NOT invalidate other notes of the same chord or make an earlier stroke's OFF release a retriggered note.
- Separate pure pattern model/editing, gesture interpretation, OFF-thread pattern/timing compilation, UI/session ownership, native flat-plan transport and DSP. Extend actual payloads deliberately; no allocations, locks, Swift/ARC work or parsing on render, no UI timers scheduling notes. Preserve bounded admission/backpressure, preallocation, sample accuracy, long-cycle rounding, smoothing/ear-safety and audition semantics.
