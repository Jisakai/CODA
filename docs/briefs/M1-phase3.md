## Implement now
1. A production native audio/transport module and narrow Swift control-side facade integrating the existing CodaMusic compiler and CodaDSP with AVAudioEngine. Keep music theory, native renderer, AV adapter and UI/control state separable and testable. Wire build/link/module exposure through project.yml only. The existing production DSP must actually supply audio; no replicated oscillators or mock-only integration. No new third-party runtime dependency.
2. The actual render callback and all per-sample/per-buffer work must be native C/C++/ObjC++ with preallocated state. No Swift/ObjC object messaging, retain/release-heavy blocks, allocation/deallocation, locks, waits, dispatch, logging, I/O, parsing, timer scheduling or UI work from the render callback. A control-side Swift facade may own/manage the adapter, never be called by render. Verify real Apple AVAudioSourceNode/AVAudioEngine callback signatures and lifecycle APIs against primary docs; do not guess SDK APIs. Document a narrow unavoidable API boundary precisely instead of claiming all framework internals were audited.
3. OFF-thread compilation from the real Progression/NoteEventCompiler to native flat POD event plans, with an explicit bounded lock-free publication/acknowledgment/reclamation scheme. Native render owns stable immutable published storage, and old plans/storage are reclaimed outside render only after safe acknowledgment. Do not let a Swift Array or temporary pointer escape its lifetime. Capacity/full/invalid-plan failures must be observable and recoverable on the control side, never silently drop notes or controls. Serialize all producers. The current DSP event FIFO has 1023 usable slots and 32 events/sample: the adapter must satisfy those contracts, not merely assume capacity.
4. Sample-accurate transport: play, pause/stop, restart, seek/scrub, tempo changes, loop toggle and whole-bar loop bounds on the 8-bar/16-step canvas. Long-running loop timing must use absolute/cycle-indexed boundaries without cumulative rounding drift. At a loop wrap, terminal offs precede new ons, and region IDs are cycle/plan-safe so stale offs cannot release a new chord. Empty spans/empty loops are silent. Nonloop playback ends correctly and cannot leave held notes. Do not reset the DSP at each loop boundary; preserve overlapping releases and FX tails. No control-thread timer responsible for note timing, and no render dependence on UI responsiveness or continuous Swift refills. Native scheduler may feed precompiled events into DSP on render if bounded and exclusively owned; document why producer ownership is valid and how controls stay serialized.
5. Treat plan updates while playing (future chord edits, BPM/loop change, seek, audition) as an explicit safe protocol. Obsolete queued notes must not fire; simultaneous playback/audition must not corrupt event ordering or region identity. Bound transition work and use smooth release/fades as needed. Support chord and candidate audition required by later Pencil UI without mutating ProgressionEditor history. Do not silently stop playback for every knob change. Preset/macros/five knobs/shared FX/Chords level/mute must forward to existing controls with coalescing/retry policy for full control queues. Respect retained-preset/release and mute invalidation behavior already documented.
6. Lifecycle safety: audio session setup outside render, engine start/stop, background/interruption and route/sample-rate changes. Enforce BOTH render and serialized producer quiescence before core prepare/reset/stop/destroy or resizing storage. Engine pause alone is not evidence an in-flight callback has returned. Prevent UAF, callbacks into destroyed owners, and blocking waits from render. On valid sample-rate changes recompile against actual engine format and prepare while quiescent. Fail quietly and observably on control side; don't pretend unavailable audio succeeded. Don't add special entitlements, microphone permissions or recording; output-only audio.
7. A practical control-side observable app/session model for the next UI slice, using existing ProgressionEditor/vocabulary/solver/suggestions rather than reimplementing music logic. No new visible editor UI in this slice. Preserve working landscape lock, font registration, OLED canvas and current launch tests. No preloaded progression or temporary demo buttons in ordinary launch. Expose narrow APIs the next slice can use rather than adding fake settings or nonfunctional controls.
8. Real automated tests of production native scheduling/publication and actual AV adapter where feasible on Mac/simulator. Exercise irregular block sizes, exact onset/off order, many loop wraps/fractional BPM, region uniqueness, empty spans, nonloop end, plan swap while active, pause/restart/seek, backpressure, malformed/capacity limits, rapid controls/preset/mute, producer/render concurrency and reclamation, teardown/reprepare and sample-rate changes. Instrument new native render work for zero allocations/deallocations. Preserve all existing DSP tests and run new portable tests under normal and ASan/UBSan paths. Native tests must use production code, not a Python replica. A bounded offline AVAudioEngine manual-render test is useful if supported: no output hardware needed and no claim of subjective sound/physical latency.
