## Implemented interface and producer contract

`CodaPerformanceCycle` owns a fixed 3072-event POD array, explicit uint64 cycle index, absolute sample origin and positive sample count. Events retain their relative sample offsets and all pitch/rank/harmonic/attack/velocity/modulation payload. `owner.instance` is a nonzero compiler-local identity unique among ONs within the cycle. Caller `owner.prepare_epoch`, `plan_generation`, `cycle`, and `activation` MUST all be zero, including OFFs. The enclosing cycle index supplies the cycle; callers cannot assert native runtime identity. Harmonic tokens must be nonzero and are independent of instance and ascending rank.

`coda_transport_publish_performance(transport, plan, &generation)` validates immutable payloads then returns 1=QUEUED, 0=full, -1=invalid/unprepared/exhausted. Queue success assigns a nonwrapping generation, not application. Four configuration slots allow three occupied including the retained active slot. A separate fixed slot-index mailbox preserves latest-cumulative-snapshot semantics. The producer owns occupancy metadata; the consumer release-publishes per-slot retirement only after its last access. The active slot remains pinned across rejected replacements, so rejected generations can be reclaimed without losing active storage. Legacy publication shares this ordering and retains existing playback behavior.

The consumer checks the latest pending performance snapshot BEFORE releasing notes, changing active pointers, consuming command revisions, or mutating playback. Ordinary updates must match the authoritative musical cycle, including the next cycle at a pending wrap. Stale initial cycles publish rejected_generation plus required_cycle and retire only the rejected slot. Prior intent, notes and phase continue; earlier pending cumulative snapshots are superseded. A new explicit position revision or explicit restart from completed playback authorizes a cycle selection. Retry by compiling the required current cycle and publishing the SAME unconsumed cumulative command revisions/values; a later boundary may require another retry. No status observation decides admission.

Every configuration slot owns its own four-cycle SPSC refill lane, capacity three including a consumed active cycle. Producer metadata retains generation, rate, length and last admitted cycle. `coda_transport_enqueue_performance_cycle` finds the requested retained generation, including ACTIVE while another generation is pending; validates consecutive cycle and exact absolute boundaries using that generation's timing; and copies only into its lane. Return 0 preserves the identical-cycle retry. Return -1 means invalid/nonconsecutive or safely retired generation. A newly queued generation cannot overwrite/discard ACTIVE cycles, and the old consumer never reads/discards a new generation's lane. Lane head/tail reset only after slot retirement and reuse. Exactly one serialized control producer is required across every publish/refill API. Lifecycle requires full quiescence.

Absolute origin/count validation, 2^53 grid precision guards, one-sample fractional absolute seek regression, exact sample preservation for unchanged timing, and musical step preservation for tempo/range changes remain. Ordinary updates preserve the compiled cycle; explicit seeks round cycle-plus-step once before subtracting origin. No cycle-zero replay or compilation occurs on render.

## Runtime lifecycle and recovery

Every successful prepare increments a nonwrapping epoch over the object's lifetime. Each configuration has its own nonwrapping generation. Restoration allocates a fresh nonwrapping activation. Each emitted ON receives epoch/generation/cycle/activation/local-instance qualifications. Its exact qualified owner is retained separately from rank in twelve fixed held slots; OFF retrieves the original activation. Restoration replays the already compiled list only to reconstruct held instances and skips represented due events, then follows their remaining exact OFF schedule. No event compilation occurs on render.

Pause, seek, replacement and mode changes retire held ownership. Audition stays in the legacy DSP ownership domain, which is isolated from performance OFFs; its region identities do not wrap. Replacement, expiry and cancel release audition voices and restore the current flat-cycle state with fresh activation. Terminal compiled OFFs are delivered before switching cycles, preserving OFF payload, with OFF-before-ON ordering. Lifecycle batches coalesce due events through reconstruction: at most twelve releases plus twelve replacement ONs. The DSP FIFO is drained every sample by the same native scheduler.

At an absent exact next cycle, release happens once, underrun count increments once, musical position waits at the boundary and the audio/FX clock continues. A later matching refill resumes at local sample zero on the next render sample and clears underrun state. Audio time therefore includes the stall; musical offsets within the supplied cycle remain exact. No timers schedule notes.

`coda_transport_performance_status` exposes observational atomic epoch/active generation/cycle/requested cycle/active-lane queued/underrun and explicit applied_generation/rejected_generation/required_cycle acknowledgements. They are individually atomic, not one transactional snapshot. Rejection generation acquire precedes required-cycle read. Status is a retry hint, never admission authority. Producer metadata owns the successful refill sequence. Diagnostics require consumer quiescence.

Admission rejects rather than truncates malformed payload, >3072 events, >32 at a sample, >12 simultaneously held notes, duplicate ON instance, simultaneous same-pitch ownership, unmatched/wrong-pitch OFF, leftover held notes, unsorted timing, OFF-after-ON ties, endpoint ON, nonfinite/out-of-range modulation and nonpositive velocities. Terminal OFF at sample_count is allowed. With strict OFF-before-ON and twelve held notes, the maximum actually valid same-sample lifecycle is 24 events; a valid 32-event case is mathematically unreachable under these combined constraints. The independent 32 guard remains. Tiny positive native Float remains valid; Swift Double-to-Float underflow handling is deliberately pending the bridge slice. No new feel defaults or dependencies.
